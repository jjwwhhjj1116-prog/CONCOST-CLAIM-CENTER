# P13 독립 검수 및 보정 메모

Antigravity 구현 커밋 851b3b9e032958bab0ab8745ba4f171ca44f1814와 제출 커밋
5e65eff7adf87d0e118668cac6f2d24767638f7e를 독립적으로 확인했습니다.

초기 제출에는 권한·독립 승인·정확한 원화 계산·멱등성·종결 불변성·이전 DB 업그레이드·
사건 전환 UI·증거 정합성에 Critical/High 문제가 있어 그대로는 FAIL이었습니다.
사용자가 허용한 patch-mode에 따라 Codex가 구현을 보완했고,
최종 검수 대상은 5e7736a2ad21ae2361075bf73857ae783b3784bc입니다.

주요 보완 결과:

- 조직과 사건 배정 경계를 조회·변경·DB trigger 전 영역에서 강제했습니다.
- 예상 계산과 Director/CEO 독립 확정을 분리하고 self-approval을 차단했습니다.
- KRW 정수·bps·half-up 계산과 부가세 포함/별도 계산을 서버·UI·DB에서 일치시켰습니다.
- 계산·확정·수납의 동시 동일 멱등 키 재시도를 단일 결과로 수렴시켰습니다.
- 수납·조정·미수 종결·일반 상태 변경 우회를 원자적 version 경계로 차단했습니다.
- CLOSED 사건의 API 및 raw DB 재무 변경을 차단했습니다.
- 기존 P13 DB의 정상 이력은 보존하면서 오염된 scope, 구식 조정 의미, 위조 표식은 fail-closed 처리했습니다.
- 구식 V1 확정본은 열린 사건에서 DRAFT로 격리해 V3 재계산과 독립 승인을 요구합니다.
- FEE-01을 실제 서버 API 기반 화면으로 연결하고 사건 검색, 승인자 배정, 이력, 미수 경고,
  1024/640 반응형, 키보드 흐름, 사건 전환 경쟁 상태를 검증했습니다.

고정 Node 20.18.0과 pnpm 9.15.0의 깨끗한 checkout에서 11개 게이트를 모두 통과했습니다.
일반 테스트 90/90, 보안 테스트 62/62, P13 직접 검증 19/19,
실제 Chromium P06~P13 8개 흐름, 고위험 취약점 0건입니다.

보안 스캔 결과 API 키·토큰·클라이언트 비밀·개인키·실제 고객정보는 발견되지 않았습니다.
테스트 데이터는 example.invalid 등 결정론적 합성 fixture만 사용합니다.

판정은 PASS_WITH_NOTES이며 P14 진입을 허용합니다.
비차단 Low 1건은 주요 화면의 픽셀 기반 screenshot baseline이 아직 없다는 점으로,
P15 통합 안정화에서 추가하면 됩니다.

업그레이드 운영 주의:

- 구식 V1 확정 설정은 의도적으로 재검토 상태가 되므로 담당자가 V3 재계산과 독립 승인을 수행해야 합니다.
- 구버전 ADJUSTMENT는 신·구 의미가 반대여서 자동 변환하지 않고 migration을 fail-closed합니다.
  운영 데이터에 존재하면 사전 회계 검토 후 명시적으로 정리해야 합니다.
