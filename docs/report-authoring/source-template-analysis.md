# 보고서 원본 템플릿 분석 기준

## 분석 범위

- 사내 원본 폴더의 32개 파일(PDF, HWP, HWPX, XLSX)을 파일명만 보지 않고 본문·목차·표 구조까지 추출해 분석했다.
- 원본은 9개 업무 분류이며, 웹의 6대 클레임 유형에 주·보조 유형으로 연결한다.
- 원본 문서에 포함된 고객명, 사건번호, 금액, 개인정보는 새 보고서에 복제하지 않는다. AI는 현재 프로젝트에 연결된 근거만 사용한다.

## 원본 분류와 보고서 유형 연결

| 원본 분류 | 파일 수 | 주 유형 | 보조 유형 | 핵심 작성 구조 |
|---|---:|---|---|---|
| 감정보완 신청서 | 6 | TYPE-02 | - | 감정보완 대상, 보완사항, 입증취지, 질문·증빙 |
| 항소에 대한 의견 보고서 | 2 | TYPE-02 | - | 항소 주장, 감정인 의견, 쟁점별 반박, 제출전략 |
| 설계변경+물가변동+간접비 | 2 | TYPE-06 | TYPE-03 | 계약·변경 연혁, 산정기준, 직접·간접비, ESC |
| 하자검토 보고서 | 1 | TYPE-01 | TYPE-02 | 하자 범위, 조사기준, 항목별 판단, 보수비·귀책 |
| 설계변경+물가변동 | 1 | TYPE-06 | TYPE-02 | 기준·비교시점, 지수·품목, 조정금액, 종합의견 |
| 공사비 적정성 검토 보고서 | 14 | TYPE-04 | TYPE-02, TYPE-06 | 과업개요, 공종별 검산, 시장비교, 협상·재검토 |
| 하자조사 보고서 | 2 | TYPE-01 | - | 현장조사, 하자 유형, 사진, 보수공법·수량·금액 |
| 돌관공사비 보고서 | 2 | TYPE-03 | - | 공기단축 지시, 투입시간·인력·장비, 인과·정산 |
| 기시공·미시공 보고서 | 2 | TYPE-01 | TYPE-03 | 현장조사, 기시공·미시공·오시공, 기성고율·내역 |

TYPE-05는 대응하는 전용 원본이 없으므로 `TEMPLATE_NOT_FOUND`를 유지한다. 다른 유형의 원본을 임의로 대신 적용하지 않는다.

## 챕터 프롬프트 생성 원칙

1. 각 챕터는 역할, 입력 근거, 작성 순서, 수치 검산, 금지사항을 별도로 가진다.
2. 원본의 목차 흐름을 따르되 현재 프로젝트의 제안서, 착수회의, 현장조사, 수량산출, 자료실, 법원자료만 인용한다.
3. 읽지 못했거나 충돌하는 근거는 추측하지 않고 `[확인 필요]`로 남긴다.
4. 관찰 사실, 기술 판단, 계약상 판단, 금액 영향, 유보사항을 섞지 않는다.
5. 합계와 산식은 하위 항목과 다시 계산하고, 날짜·버전·출처를 함께 표시한다.
6. 법률 결론과 책임 귀속은 사람 검토 전 확정하지 않는다.
7. 프롬프트 원문과 변경 권한은 Admin에게만 있으며, 변경 이력은 append-only로 보존한다.

## 원본 저장·열람 경계

- 원본 파일은 공개 Git, Worker 정적 자산, D1 BLOB, 외부 AI 입력에 넣지 않는다.
- 회사 Google Drive의 비공개 `CONCOST CLAIM CENTER - 보고서 템플릿` 폴더 아래 9개 분류 폴더에 저장한다.
- D1에는 파일 ID, 분류, 이름, 크기, SHA-256, 업로더, 업로드 시각만 기록한다.
- 등록은 Admin만 가능하고, 로그인 사용자는 보고서 작성 화면에서만 열람한다.
- PDF는 인증 프록시로 브라우저에서 열며 HWP/HWPX/XLSX는 인증 후 원본 다운로드한다.
- 다운로드 때 Drive 바이트 수와 SHA-256을 D1 메타데이터와 다시 비교한다.
