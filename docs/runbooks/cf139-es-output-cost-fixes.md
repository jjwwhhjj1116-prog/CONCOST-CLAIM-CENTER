## 확인된 원인과 변경

- `%` 문자열을 값에 붙이면서 원본 `%` 전용 셀/숫자 서식과 중복됐다. `:percent`를 원본 서식에 맞는 숫자 projection으로 변경. 긴 순환소수는 출력 정밀도로만 반올림하여 Excel에서도 숫자 서식을 사용한다. 원본 입력·K·계산 결과는 변경하지 않는다.
- 산재요율 `4/4.!D165,H165`의 `/100` 표시 변환 누락을 복원했다. 다른 중간지수/요율 숫자에는 적용하지 않는다.
- 공정률 원본 관계: `1!J21='2'!C13/100`, `1!J22='2'!C14/100`; `2/2.` 원자료 셀은 숫자+별도 `%`. 저장값은 유지하고 `1`의 두 출력만 `/100`, 입력 라벨은 `(%)`로 명확화. 50은50%, 0.5는0.5%이다.
- 선금표 C7 등 축소 미지정 텍스트도 폭을 검사한다. 표 안의 한글은 단어 단위 줄바꿈, 필요 시 행 높이를 재측정한다. 긴 숫자도 측정 후 맞춘다. 테두리 없는 원본 설명문은 데이터/테두리/원본 병합을 침범하지 않는 빈 옆칸 공간을 사용한다. Excel 원본 병합·좌표·폰트·행 데이터는 보존.
- 서술형 금액 근거에 천 단위 쉼표·원 단위를 추가하고 선금 대상액0일 때 0으로 나누는 설명식을 표시하지 않는다.
- 금액 입력 포커스 시 쉼표 제거가 선택 영역을 해제하는 문제를 실제 React/Chromium에서 재현했다(100,000을200,000으로 교체 시100,000,200,000으로 붙는 경우). 포커스는 값을 바꾸지 않고 첫 입력 이벤트에서 편집 표시로 전환한다. 쉼표 제거 수만큼 커서 위치도 보정하여 중간 삽입의 숫자가 끝에 붙지 않도록 검증했다. 실제 키보드 Home→ArrowRight→99, 전체선택 교체 모두 PASS.
- 비목 화면에 비목 합계/적용대가, 금액 있음·0원·미입력 개수, 가져오기·공제 확인 동선을 표시했다. Ponytail로 기존 입력·저장 경로를 사용하고 Impeccable clarify 원칙으로 서로 다른 금액의 의미를 분리했다. 새 라이브러리 없음.

## 원본 대조 결론

- 사용자 원본의 기본입력!C16은 총계약금액. 3!B열 지정28개 비목은 수동값/빈칸이며 수식이 아니다. B45는 비목 합계, 계수는 비목/B45이다. 총계약금액으로 비목을 임의 배분하면 안 된다.
- 총계약금액−기성 제외액−중복을 뺀 직접 지급액이 적용대가에 연결된다. 비목 구성비가K를 결정한다. 모든 비목을 같은 비율로 바꾸면K는 그대로다.
- 선금 대상금액E10/지급액E11은 별도 원자료. 총계약금액을 선금 대상금액에 임의 복사하지 않는다.
- 읽기 전후 원본 SHA 동일. 공개자료/날짜 동기화/저장이 비용을 덮지 않는 경로를 독립 확인했다. Excel 가져오기 확정은 전체 입력 교체이므로 기존 비교·확정 절차를 유지한다.
