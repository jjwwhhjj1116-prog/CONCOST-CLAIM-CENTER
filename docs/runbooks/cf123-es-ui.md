# CF123 ES 작업화면 구현 기록

## Overview

2026-09-08 기준 ES 전용 UI 런북이다. Impeccable `document`의 구현 추출 원칙을 적용하되, 사용자 지정 범위에 따라 이 파일만 작성한다. 기존 클레임센터의 **Operate 확장**이며 사이트 재설계가 아니다. 총괄이 확인한 좁은 작업 예외를 적용하여 루트 `PRODUCT.md`, `DESIGN.md`, 디자인 sidecar를 만들거나 변경하지 않는다.

독립 검수의 최신 UI 한정 판정은 `ship`이다. 이는 아래 로컬 화면·상호작용 범위에 한정하며 **ES v2 전체 계산, 원본과 동일한 출력, 실제 Excel 재계산·네이티브 인쇄 또는 운영 배포 승인이 아니다.** 기존 클레임센터 이름·로고·메뉴 체계를 보존한다. HWP 기능 추가나 기존 HWP 변경은 이 범위에 없으며 운영/가오픈 서버에 배포하지 않는다.

구현 기준은 `apps/web/src/es/EsStudio.tsx`, `EsStudio.css`, `apps/web/src/layout/AppShell.tsx`, `apps/web/src/theme-system.css`이다. 라우트는 `apps/web/src/routes/Router.tsx`, 서버 접근 계약은 `packages/document-engine/src/es-service.ts`, 페이지 초안은 `apps/web/src/es/EsPrintPreview.tsx`를 함께 확인했다. 아래 값은 ES 범위의 관찰값이며 전역 디자인 규칙으로 승격하지 않는다.

## Typography

새 글꼴을 도입하지 않는다. 공통 테마의 한국어 글꼴 설정과 `Noto Sans KR`, Manrope, system-ui 계열을 상속한다. ES 본문은 14px, 필드 표시는 13px/600, 제목은 26px, 구역 제목은 18px이다. 모바일 작업창 제목은 20px로 줄어든다. 금액 입력·표·요약은 tabular numbers를 사용하며 금액 입력은 오른쪽 정렬이다. 원본 셀 위치 보조문구는 10px이므로 주 정보나 필수 오류를 이 크기에 의존시키지 않는다.

## Layout

- 메뉴 순서는 `프로젝트 워크 → ES 산출프로그램 → 드라이브`이다. ES는 펼침 하위 메뉴가 없는 독립 최상위 진입 버튼이다. 설정은 스크롤 메뉴와 분리된 하단 footer에 남으며 기존 상단 설정 단축 버튼도 유지한다.
- `/es`는 목록·검색·새 산출서 진입, `/es/editor`는 새 작업창이다. 저장 문서는 `/es/editor?documentId=…`로 다시 진입한다. 첫 저장 성공 시 문서 ID 주소로 교체한다.
- 편집기는 `document.body` portal 안의 주소 지정 가능한 모달이다. 데스크톱 폭 94vw, 높이 92vh, 최대 폭 1600px이다. 800px 이하에서는 100vw × 100dvh의 전체 화면과 각진 외곽으로 바뀐다.
- 헤더·도구막대·하단 요약은 작업창의 고정 flex 영역이다. 가운데 작업 영역만 세로 스크롤된다. 요약은 현재 K, 직전일 K, 적용대가, 선금 공제, 최종 조정금액을 유지하며 불완전 입력은 `계산 대기`로 표시한다.
- 기본입력은 2열, 600px 이하에서는 1열이다. 비목과 원자료 기간 구역은 1100px 이하에서 1열로 바뀐다. 넓은 원자료 표는 표 컨테이너 안에서 스크롤하며 전체 페이지를 가로로 밀지 않도록 한다.
- 출력 시트 선택은 3열 → 1100px 이하 2열 → 600px 이하 1열이다. 17개 시트가 17페이지라는 가정은 금지한다.

## Elevation & Depth

작업 도구막대는 얕은 그림자 `0 2px 8px #18304912`를 사용한다. 작업창은 `#172b465c` 배경막 위에 `0 20px 70px #12253c55` 그림자로 기존 화면과 구분한다. 새 장식·랜딩 페이지식 연출·새 브랜드 이미지는 도입하지 않는다.

## Shapes

기존 업무 폼과 유사한 작은 모서리를 유지한다. 버튼 6px, 입력 5px, 도구막대·작업 구역 8px, 데스크톱 모달 12px이다. 버튼·입력의 최소 높이는 36px이다. 이 수치는 전체 모바일 터치 대상이 44px 이상이라는 보증이 아니다.

## Components

### 문서와 접근 계약

ES 문서는 사건을 강제로 만들지 않는 독립 문서다. 프로젝트 연결은 선택이며, 목록 요청 실패 시에도 연결 없이 작성할 수 있음을 안내한다. UI의 작성자·관리자 안내는 권한 집행의 대체물이 아니다. 서버는 회사 일치와 `(작성자 일치 또는 관리자)`를 함께 검사하고, 프로젝트를 연결할 때 별도 `canLink` 검사를 수행한다. 프로젝트 연결만으로 다른 사람에게 ES 문서 접근이 자동 부여된다고 설명하지 않는다. 저장소·실서버 ACL 검증은 격리 UI mock 결과와 분리한다.

### 여섯 작업 영역

| 순서 | 화면 이름 | 현재 구현 |
| --- | --- | --- |
| 1 | 기본입력 | 제목, 선택적 프로젝트, 발주자·시공자, 기준/조정일, 계약금액 |
| 2 | 비목·적용대가 | 원본 위치를 표시하는 28개 비목 금액과 한 열 붙여넣기 |
| 3 | 지수·요율 | 기준/현재/직전 원자료, 요율, 기간쌍과 출처의 수동 입력; 자동 API 미연결 표시 |
| 4 | 선금·공제 | 현재 지원하는 기성·직접지급·선금·기타 공제 입력 |
| 5 | 계산검토 | 현재 입력의 오류·경고, K·금액 및 비목별 계산표 |
| 6 | 출력물 | Excel 가져오기 확인, 작업용 내보내기, 17개 시트 선택, 저장 run 기반 초안 미리보기 |

영역 전환은 이름 있는 `nav` 안의 네이티브 button과 `aria-current=page`를 사용한다. ARIA tablist/roving-tabindex 또는 화살표 키 탭 이동을 구현했다고 표현하지 않는다.

### 입력, 초점과 이동 보호

- label로 묶인 input/select/textarea, 날짜 input, 파일 input, checkbox와 button 등 브라우저 기본 제어를 사용한다. 계산 금액·표 입력에는 이름을 제공하고 오류는 `role=alert`, 처리 상태는 `role=status`로 전달한다.
- 모달은 `role=dialog`, `aria-modal=true`, 제목 연결과 초기 초점을 갖는다. 배경 앱 `#root`만 inert로 하고 body는 스크롤을 잠근다. body 전체를 inert로 하는 구현은 아니다. Tab/Shift+Tab은 보이는 제어의 첫/끝에서 순환하며 닫힐 때 기존 inert·스크롤 값을 복원한다.
- 닫기와 Escape는 `/es` 이동 경로를 사용한다. 미저장 변경에는 폐기 확인, 처리 중에는 이동 차단, 새로고침/이탈에는 beforeunload 보호가 있다. 이 코드 존재와 실제 브라우저 뒤로가기·새로고침의 모든 조합 검수는 구분한다.
- 원래 실행 버튼으로 초점을 되돌리는 명시적 복원 코드나 스크린리더 전체 검수는 확인되지 않았다. 격리 테스트가 확인한 것은 초점 순환과 Escape 취소/확인·배경 복원이다.

### 저장, 실행 취소, 붙여넣기

- `저장`은 서버 성공 응답 후 저장 상태를 갱신한다. `저장·계산`은 해당 저장 revision의 run을 요청한다. 불러오기 실패 시 덮어쓰기를 차단하고, 충돌 오류는 현재 입력을 유지하며 저장본 재확인 동작을 제공한다.
- 실행 취소/재실행은 입력 스냅샷 버튼이다. 일반 입력 변경은 최대 50개 이력 범위를 유지한다. 프로젝트 연결 값은 이 입력 스냅샷과 별개이므로 프로젝트 연결의 undo까지 지원한다고 설명하지 않는다. 서버 revision 삭제나 문서 전체 변경 이력 복구 기능도 아니다.
- 여러 비목에 붙여넣을 때 한 열의 줄바꿈 숫자를 받아 쉼표를 제거한다. 복수 열, 잘못된 숫자, 남은 행 초과는 거부한다. 한 번의 여러 행 붙여넣기는 한 번의 undo로 되돌린다. 일반 단일 셀 텍스트 붙여넣기는 기본 입력 동작이다.
- Excel 가져오기는 `.xlsx`, 25MB 이하를 받아 적용 전 요약과 취소/적용을 제공한다. 적용은 메모리 입력 교체이며 자동 저장이 아니다. 모든 값·셀의 전후 비교표나 원본 전체 수식 변조 감지 완료를 뜻하지 않는다.

### 출력 상태와 승인 경계

미리보기·보고서 Excel은 현재 입력이 저장되어 있고 run revision이 문서 revision과 같을 때 열린다. 시트 선택 0개이면 전체/선택 보고서 Excel 버튼도 비활성이다. 작업용 Excel은 별도 입력 백업 동작이다. 저장 문서 재진입만으로 기존 run이 자동 복구되지 않아 출력을 위해 다시 저장·계산해야 한다.

시트 선택과 인쇄 페이지 범위는 다르다. Excel은 선택 시트 전체를 내보내며 인쇄용 페이지 범위로 Excel을 자르지 않는다. 현재 A4 페이지는 원본 17시트 서식의 충실한 복제가 아닌 재구성 초안이다. UI와 페이지의 미승인·초안 경고를 유지한다. 작업용 수식 확장이 있어도 실제 Microsoft Excel 재계산과 원본 17시트 연결 검수 없이는 호환성 완료로 승격하지 않는다. 출력 기록의 REQUESTED/RENDERED/DIALOG_CLOSED는 물리 프린터 성공을 의미하지 않는다.

## Do's and Don'ts

- Do 기존 메뉴·이름·시각 정체성과 저장/권한 경계를 보존하고, 빈 입력과 금액 0을 구분한다.
- Do 최신 소스와 같은 UI revision의 증거를 연결한다. 과거 인라인·4탭 검수는 최신 모달 증거로 재사용하지 않는다.
- Do 비식별 합성 데이터만 문서·화면 예시로 남긴다. 원본 고객값, 원본 workbook, 비밀키를 이 런북이나 저장소에 추가하지 않는다.
- Don't UI 한정 `ship`을 전체 ES v2, 원본 계산 쟁점 해소, 원본 서식 동일성 또는 공식 제출용 승인으로 확대하지 않는다.
- Don't HWP 추가, 기존 업무 기능 재설계, 운영/가오픈 배포를 이 기록의 후속 자동 동작으로 수행하지 않는다.

### 확인된 로컬 증거

최신 기록은 `output/playwright/es-v2/QA_NOTES.md`와 `results.json`의 `PORTAL_MODAL_SIX_TABS_UNDO_PASTE`이다. 실제 앱 컴포넌트를 사용한 **격리 headless Chromium + 인메모리 API mock** 10개 검사가 PASS이며 page error와 unmocked request는 0개로 기록되어 있다. 이 문서 작업에서 브라우저 시험을 새로 실행한 것은 아니며, 기록과 소스 및 데스크톱/모바일 이미지 표본을 확인했다.

### 남은 검수와 이전 기록 해석

실제 로그인/업무 DB 전체 흐름, 교차 사용자 서버 RBAC UI E2E, 브라우저 125%/150% 확대, 실제 Excel 연쇄 재계산, 네이티브 인쇄창·물리 출력, 기존 타모듈/HWP 회귀, 원본 출력의 내용·서식 동일성은 이 UI 승인에 포함되지 않는다. 신규비목·후속 차수·복수 선금 등 전체 v2 계산 범위 및 알려진 원본 계산 쟁점 역시 별도 검수 대상이다.

`cf123-es-gaps.md`와 `cf123-es-acceptance.csv`는 전체 요구 판단의 별도 기록이다. 이전 스냅샷의 4탭/인라인 UI, 8개 브라우저 검사, 선택 0개 관련 설명은 위 최신 소스·10개 검사와 구분해야 한다. 이 런북은 해당 전역 판정 문서를 수정하거나 미실행 항목을 PASS로 바꾸지 않는다.
