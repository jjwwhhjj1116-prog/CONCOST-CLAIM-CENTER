# 법원 사건 조회·소송기록 관리 요구사항

## 목적

납품 이후에도 프로젝트별 소송 진행을 놓치지 않도록 법원 사건번호, 법원·재판부, 기일, 제출·송달·판결 이력을 검색 가능한 타임라인으로 관리합니다. 이 기능은 법률 판단을 자동화하는 기능이 아니라, 담당자가 확인한 공식 기록과 내부 업무를 연결하는 기능입니다.

## 범위

1. 프로젝트 하나에 복수 법원 사건을 연결할 수 있습니다(본안, 항소, 별도 감정사건 등).
2. `법원명`, `사건번호`, `사건명`, `재판부`, `당사자`, `접수일`, `현재 단계`, `다음 기일`을 저장합니다.
3. 사건번호·법원·당사자·프로젝트명으로 서버 검색하고 배정 사건 및 조직 경계를 적용합니다.
4. 기록은 `접수`, `송달`, `서면 제출`, `감정`, `기일`, `판결`, `항소`, `종결` 유형으로 시간순 표시합니다.
5. 각 기록에 담당자, 입력 경로, 공식 원문 URL, 조회 시각, 첨부 근거, 변경 이력을 연결합니다.
6. 법원 일정은 프로젝트 캘린더와 담당자 업무에 동시에 반영합니다.
7. 보고서 작성 에이전트는 사람이 검증한 기록만 근거로 선택할 수 있습니다.

## 외부 법원 조회 정책

- 공식 API 또는 이용이 허용된 공식 조회 경로가 확인된 경우에만 자동 조회를 구현합니다.
- CAPTCHA 우회, 비공개 계정 공유, 이용약관을 위반하는 자동 크롤링은 구현하지 않습니다.
- 공식 연동이 없는 경우 담당자가 조회 결과를 입력하고 원문 링크·조회일·검증자를 남깁니다.
- 외부 결과는 바로 확정하지 않고 `조회됨 → 담당자 확인 → 검증완료` 상태를 거칩니다.
- 사건번호만으로 다른 조직·미배정 프로젝트의 기록을 열람할 수 없도록 서버에서 권한을 검증합니다.

## 화면

- `납품 후 관리 > 법원 사건·소송기록`
- 상단: 사건번호·법원·당사자 통합검색
- 중앙: 프로젝트별 소송 사건 카드와 다음 기일
- 상세: 소송 타임라인, 자료, 담당자, 법원 원문 확인 정보
- 상태: 미연결, 조회대기, 확인필요, 검증완료, 조회오류

## 구현 단계

1. D1 내부 레지스트리·검색·기일 연동
2. 납품 후 관리 UI와 프로젝트 캘린더 연동
3. 공식 조회 가능성 및 이용조건 확인 후 외부 커넥터 별도 적용
4. 검증된 소송기록을 보고서 근거 Manifest에 연결
