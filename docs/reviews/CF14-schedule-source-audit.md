# CF14 프로젝트 일정표 원본 대조 기록

검토 기준 원본: `https://github.com/eumditravel-oss/schedule_sub` (`main`)

## 판정

현재 `ProjectWorkflowSchedule`은 원본의 화면 개념을 참고한 **정적 프론트 모델**이며, 원본 일정 시스템을 실제로 이식한 상태는 아니다. 따라서 `schedule_sub 기반 구현 완료`로 표시하지 않는다.

## 원본에서 확인한 핵심 계약

- `/projects` 전체·진행·완료 프로젝트 및 30일/월 간트
- `/projects/:projectId` 공정 그룹, 세부 작업, 담당자, 드래그 순서, 상태 및 일정 관리
- 한국·베트남 휴일, 베트남 토요일 근무, 개인 휴가를 반영한 근무일 계산
- 프로젝트별 인력 배정, 작업 충돌·용량 경고, 일정 이동 이력
- 모바일 30일 간트·요약·주간 보기와 A4/A3 출력
- Worker API와 D1에 프로젝트·공정·작업·배정 데이터를 영속 저장

## 현재 클레임센터 구현 상태

| 항목 | 현재 상태 | 후속 조치 |
| --- | --- | --- |
| 월간 프로젝트 바 | 정적 샘플 3건 | 수주 확정 D1 프로젝트 조회로 교체 |
| 1~6단계 상세 | 정적 화면 존재 | D1 단계·작업·버전 API로 교체 |
| 한국 인원/VIETQS 팀 | 표시용 정적 모델 | `preview_workforce_allocations`와 일정 연결 |
| 30일/월 전환 | 버튼만 존재 | 날짜 범위 계산·이전/오늘/다음 동작 이식 |
| 공휴일·휴가 | 미구현 | 원본 work calendar 계약을 클레임 업무에 맞게 이식 |
| 작업 편집·충돌 | 미구현 | D1 낙관적 버전, 배정 충돌, 감사이력 추가 |
| 모바일·인쇄 | 기본 반응형만 존재 | 640/1024 및 A4/A3 검증 추가 |

## 적용 순서

1. `제안서 연동 → 수주 확정`을 실제 D1 데이터로 전환한다. 수주 확정 프로젝트만 일정표 대상이 된다.
2. 원본의 project/task group/task 구조를 클레임 1~6단계에 맞춘 additive D1 스키마로 이식한다.
3. `수량산출·내역작성`은 한국 본사 인원별, VIETQS 내부 1~3팀 등 베트남 조직은 팀별로 배정한다.
4. 프로젝트 전체 간트와 상세 작업 간트를 동일 날짜·근무일 계산 계약으로 연결한다.

이 문서는 원본과 현재 구현의 차이를 숨기지 않기 위한 검수 기준이며, 후속 일정표 구현 완료 시 각 항목을 실제 테스트 근거와 함께 갱신한다.
